Friendly-names toggle · alternatives to "Aa"

"Aa" was borrowed from typography UIs (font-size pickers, "match case") — it's not a real convention for showing column labels. Here are four options, ordered from most→least conventional in data tools. All four are 32px tall to match the rest of the row.

Recommended

"Labels" + state dot. Most discoverable. Matches the actual terminology in SAS/clinical data (columns have a name and a label). The dot is a tiny LED-style on/off indicator. ~70px wide.

Most explicit

"Codes / Labels" segmented. Most self-explanatory — shows both options and which is active. Tells the user explicitly that there are two view modes. Slightly wider (~110px).

Smallest

Tag icon. 32px square, smallest footprint. Tag = "label" is reasonably universal. Cost: requires hover tooltip for discoverability. Best if you're tight on horizontal space.

Original (not a standard)

"Aa" glyph. Compact, but borrowed from typography UIs — users will read it as "font size" or "match case" before they'll read it as "column labels." Worst on discoverability.

My pick: the "Labels" + dot variant. Honest naming, visible state, ~70px (compared to today's "Friendly Names" checkbox at ~110px), and it teaches the user the concept rather than relying on icon-guessing. If you want even more clarity, the segmented "Codes / Labels" version is unambiguous at the cost of ~40 more pixels.

File pill · empty vs. loaded emphasis

The empty state needs to draw the eye — it's the gateway to using the app. The loaded state should be quiet so the user can focus on data. Same component, two visual weights.

Empty: ghost CTA — light purple background, purple border, purple icons. Clearly the action. Chevron at the end signals "go pick one" (replacing the swap icon since there's nothing to swap yet).

Loaded: quiet container — white background, gray border, gray icons. Hover it to see the purple border + soft glow (try it in the browser). Swap icon now appears because there's an actual file to replace.
